# BAKA — Project Context for Antigravity

## What You Are Building

BAKA is a 1.3B parameter language model built from scratch on the HOPE
architecture (Nested Learning, Google Research, NeurIPS 2025, arXiv:2512.24695).

BAKA is not a fine-tune. Not a wrapper. A new model trained from zero.

Goal: beat standard 7B transformers (Llama-2 7B, Mistral 7B) on reasoning
benchmarks despite being 5x smaller, by using a fundamentally better architecture.

---

## Why HOPE Architecture

Every model today — GPT-4, Gemini, Llama, Claude — uses the Transformer
architecture from 2017. Transformers have one fatal flaw: weights freeze
after training. The model cannot learn during inference. It has anterograde
amnesia — no new long-term memories after training ends.

HOPE solves this with three components:

1. **Delta Gradient Descent (DGD)** — a new update rule where weights decay
   based on current input. Model actively forgets irrelevant information.
   Prevents catastrophic forgetting mathematically.

2. **Self-Modifying Titans** — a sequence model where ALL projections
   (keys, values, queries, learning rates, gates) are themselves memory
   modules that update during the forward pass. The model rewrites itself
   as it reads tokens.

3. **Continuum Memory System (CMS)** — replaces MLP blocks with a chain
   of 4 MLPs updating at different frequencies (every 16, 256, 4096,
   65536 tokens). Multiple timescales of memory simultaneously.

Result: BAKA's weights change during inference. Every conversation
literally modifies the model. This is not fine-tuning — it happens
in the forward pass. This is why a 1.3B HOPE model can outperform
a 7B frozen-weight transformer on reasoning tasks.

## Training Plan

**Phase 1 — Pre-training (30B tokens)**
Objective: next token prediction
Data: FineWeb-Edu (20B) + OpenHermes (5B) + StackExchange (3B) + Python code (2B)

**Phase 2 — Reasoning SFT (50K examples)**
Objective: supervised fine-tuning on chain-of-thought reasoning traces
Data: generated by Claude/Gemini as teacher model

**Phase 3 — GRPO Self-Improvement**
Objective: reinforcement learning with verifiable rewards
No reward model needed — use code execution + math checker as verifier
Result: model improves its own reasoning through trial and error
